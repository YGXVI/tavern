# Свои существа: результат проверки (#203)

Продолжение WIP 6b8a080 от sol0139 / Codex, 05.11.2026. Рабочая ветка — claude/dev, выпуск — только в test.

Исправлено:
- Конструктор библиотеки использует общий редактор картинки: круглый предпросмотр, положение, масштаб, вписывание целиком, инициалы. Портрет не растягивает круг.
- Статблок lib-существа показывает отдельные кнопки каждого компонента урона с типом, в том числе у реакций и легендарных действий; явно заданная нулевая атака остаётся атакой.
- Перед постановкой библиотечные картинки копируются в кампанию. Снимок и токен записываются через существующий place_creature, при отсутствии RPC — прежними вставками. В серверном режиме токен показывается после ACK, отказ сообщается явно. Это распространяется также на карточку существа и простой токен игрока.
- Перед каждой новой постановкой библиотека перечитывается (включая изменения из другой вкладки); старые экземпляры сохраняют свои атаки и картинку. Изображения снимков подгружаются после перезагрузки.
- Первая новая кампания проверяет наличие таблицы снимков, даже если пользователь до этого не открывал других кампаний.

Проверки: npm test 294/294, OpenSpec 24/24 и архив 84/84; синтаксис изменённых JS/MJS и diff-check. Общий браузерный серверный сценарий — 20/20. Новый tests/browser/server-e2e/own-creature.mjs проходит через UI библиотеки: мастер 1440px и игрок 390px, полный рост, private library → campaign tokens, декодирование картинки после reload, оба компонента урона от имени участника, задержанный ACK без ложного успеха, отказ сервера, актуальная версия новой постановки, RPC и fallback, призыв, простая карточка и свой токен; ошибки JS отсутствуют.
