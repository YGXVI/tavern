# Инициатива и ведение боя

## Статус

Работающий локальный прототип; серверного боя и синхронного журнала нет. Задачи — в [../status.md](../status.md).

## Сейчас

Формулы кубов описаны в [dice.md](dice.md).

`dist/engine.js`: `roll()` и `initiativeOrder()`; `dist/app.js`: UI и сохранение; `tests/engine.test.js`: границы, ошибочные формулы и порядок. Кубы d4/d6/d8/d10/d12/d20/d100; 1…100 кубов; одна целочисленная прибавка/штраф, пример `2d6+3`. Нет произвольных выражений, встроенного преимущества или макросов атак.

Мастер бросает инициативу для всех токенов: d20 + `mod`. Порядок: `init` по убыванию, затем `mod` по убыванию, затем имя по русской сортировке; это политика демо, не полная реализация разрешения ничьих по правилам. `turn` — индекс в таком порядке, после обхода увеличивается `round`.

Новый токен без имени получает свободное `Токен N` при добавлении. Это обеспечивает отображаемое имя, но не является полной нормализацией импортированных безымянных токенов при старте боя. Лога боевых действий, урона и состояний пока нет. `logs` содержит последние 60 записей бросков/событий.

## Целевое поведение и критерии

- Мастер выбирает участников, запускает бой, видит модификаторы и может исправить результат/ничью вручную.
- Каждый участник, включая безымянного, имеет стабильный ID и различимую подпись; присвоение номера не меняется от сортировки.
- Должна быть отдельно согласована инициатива группы существ или каждого токена.
- Удаление, добавление и поражение участника в бою не приводят к случайному пропуску или повтору хода.
- Общий результат броска фиксируется единожды и распространяется участникам; перезагрузка не перебрасывает кубы.
- Закрытые броски и видимость чисел/HP врагов требуют отдельного решения.

## Границы

Правки токенных полей и порядка затрагивают карту, лист и роли. Не менять их параллельно без владельца контракта. UI не должен оценивать произвольный JS из формулы.
