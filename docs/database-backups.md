# Бэкапы баз Supabase (#204)

Бесплатный план Supabase бэкапов не даёт, поэтому дамп снимает человек на своём компьютере скриптом
[`tools/backup-db.py`](../tools/backup-db.py). Агент пароли баз не вводит и не хранит.

## Когда

- **Перед каждой миграцией живой базы** — обязательно (правило AGENTS.md: миграция только после бэкапа с проверкой восстановления).
- Тестовую базу — по желанию: её можно пересоздать из миграций, но данные тестовых партий пропадут.

## Как

1. Один раз: `brew install postgresql@17` (нужны pg_dump/pg_restore не старше сервера).
2. В Supabase нужного проекта: **Connect → Direct → Session pooler**, скопировать строку и подставить пароль базы вместо `[YOUR-PASSWORD]` (без скобок).
3. В папке репозитория:
   ```bash
   python3 tools/backup-db.py
   ```
   Скрипт спросит строку (ввод скрыт), снимет дамп и проверит восстановление.
4. В конце должно быть «Готово: N таблиц приложения, M строк восстановлены локально и совпали с архивом».

Бэкап ложится в `~/DropDiceBackups/<ref проекта>/<время UTC>/` (права только владельца): `app.dump`, `platform.dump`, `manifest.json`. Внутрь репозитория скрипт писать отказывается. Хранить копию вне ноутбука (облачный диск с шифрованием) — на усмотрение владельца.

## Что внутри

| Файл | Содержимое |
|---|---|
| `app.dump` | схемы `public` и `supabase_migrations`: таблицы, функции, политики, данные |
| `platform.dump` | данные `auth.users`, `auth.identities`, `storage.buckets`, `storage.objects` (схемы auth/storage создаёт сам Supabase) |
| `manifest.json` | версия сервера, SHA-256 файлов, число строк: в живой базе, в архиве, после восстановления |

**Не входят** файлы в бакетах Storage (картинки карт, токенов, библиотеки) — только их записи.

## Восстановление (аварийное)

В новый проект Supabase: применить `supabase/migrations/*.sql` (или развернуть схему из `app.dump`), затем данные:

```bash
pg_restore --no-owner --no-privileges --data-only -f data.sql platform.dump
pg_restore --no-owner --no-privileges --data-only -f app-data.sql app.dump
psql "<строка нового проекта>" --single-transaction -v ON_ERROR_STOP=1 \
  -c "set session_replication_role = replica" -f data.sql -f app-data.sql
```

`session_replication_role = replica` отключает триггеры-охранники на время загрузки (так восстанавливает и сам Supabase). Порядок важен: сначала пользователи, потом данные приложения. Перед восстановлением в живой проект — отдельное решение владельца.
