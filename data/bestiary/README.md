# Бестиарий D&D 5e 2014 — дополненные статы

Один файл `bestiary-2014.json`, схема **1.1.0**, обновление 30 октября 2026. Отдельная запись на существующий стабильный ID; интерфейс и игровые механики не изменяются.

## Охват

| Данные | Количество |
| --- | ---: |
| Все записи | 2 906 |
| Исходные записи индекса dnd.su | 2 875 |
| Статблоки SRD 2014, сохранённые без изменений | 334 |
| Дополненные публичными техническими статами dnd.su | 2 572 |
| Из них с числовыми КБ/хитами и всеми шестью характеристиками | 2 550 |
| Нестандартные записи / переменные хиты | 22 |

| Числовые расхождения с 5e.tools, сохранены для проверки | 31 |

22 нестандартные записи включают осадные объекты, транспорт, шаблоны спутников и особые случаи вроде хитов, зависящих от вызвавшего персонажа, или иммунитета ко всему урону. Указанные в источнике КБ/хиты сохранены; отсутствующие/условные значения остаются `null`. Нулевые характеристики и хиты не выдумываются.

## Что есть в статблоках

КБ и исходное пояснение, средние хиты и формула кубов, скорости ходьбы/полёта/плавания/лазания/копания, шесть характеристик и модификаторы, спасброски и навыки, бонус мастерства, чувства и пассивное Восприятие, языки, CR/опыт, уязвимости, сопротивления и иммунитеты.

Для новых записей dnd.su разделены `special_abilities`, `actions`, `bonus_actions`, `reactions`, `legendary_actions`. Сохраняются названия возможностей, бонусы атаки, досягаемость и дальность, Сл спасбросков и выражения кубиков. **Выражение кубиков не объявляется автоматически уроном**: оно может относиться к альтернативному режиму, исцелению, дополнительному эффекту и т. п. Поэтому `damage: null` означает, что классификация урона не выполнена, а сами выражения лежат в `technical_parameters`.

У записей, сопоставленных с 5e.tools, есть `stat_block.capabilities_5etools`: **7 101 именованная запись технических возможностей** (не обязательно уникальные способности): 2 409 особенностей, 3 588 действий, 254 бонусных действия, 166 реакций, 383 легендарных действия, 33 мифических действия, 114 логовных действий, 154 региональных эффекта. Сохранены теги типов бросков, формулы, бонусы, дальность, Сл/характеристика спасброска, упоминания типов урона, перезарядка/лимиты из заголовка и ссылки на заклинания. Эти ссылки сами по себе не означают, что существо умеет накладывать каждое упомянутое заклинание.

Полные не-SRD описания способностей, условия применения и лор **не копируются**. Числовые параметры не заменяют полное правило; ссылки на источники сохранены. Автоматический бой, расход зарядов, мультиатаки, спасброски, выбор целей и эффекты не реализуются этим JSON. `automation_ready` остаётся `false`.

## Источники и версии

- https://dnd.su/bestiary/ — открытые числовые статблоки и заголовки. Штатные перенаправления в `/multiverse/bestiary/` принимаются: это MPMM 2022 в рамках правил 5e 2014. Фактический адрес сохранён в `resolved_source_url`, если карточка была получена после перенаправления. Переходы на `next.dnd.su` не выполнялись.
- https://www.dnd5eapi.co/api/2014/monsters — ранее полученные 334 SRD-записи остались без изменений.
- https://5e.tools/bestiary.html — числовые данные прочитаны из стандартной открытой Table View (2 294 строки). Прямой файловый запрос вернул 403, а CSV-скачивание не завершилось; обхода ограничений не выполнялось. Из DOM извлечены только технические поля и названия, без полного текста и изображений. Книги MM'25/PHB'24/DMG'24 исключены.

Для 5e.tools требуется точное нормализованное имя и совпадение названия книги. КБ, средние хиты, CR и все доступные характеристики сверены с dnd.su. В 31 случае отличия записаны в `detail_import_report.5etools_conflicts`; значения dnd.su ими не перезаписываются. `core_check: conflict` означает необходимость проверки версии/опечатки/особых условий. Совпадение доступных полей не доказывает тождественность всех условий способности.

Русские и английские имена не являются ID. Старые ID, формы и варианты сохранены, разные книги/редакции не склеиваются. Оригинальные русские имена каталога не перезаписываются; недостающие английские имена прочитаны из заголовков тех же карточек.

## Схема и качество

`monsters[]` → `id`, `name`, `identity`, `catalogue`, `stat_block`, `sources`, `review`.

Статблоки имеют явный `source`. Исходная SRD-структура и новые технические поля dnd.su могут различаться по необязательным полям; проверяйте `source`/`quality`, а не предполагайте наличие полного текста. Пустые списки dnd.su означают отсутствие перечисленного/извлечённого поля в заголовке; дополнительные условные защиты могут быть описаны в особенностях источника.

`coverage`, `detail_import_report`, хеши входных данных, время получения карточек и правила `null` находятся внутри JSON. Цена, изображения, комментарии и персональные сведения не собирались.

Проверки: ровно 2 906 уникальных ID, ни одной потерянной записи; все 334 прежние SRD-записи побайтно по данным совпадают с исходными; для 2 572 новых записей сверены КБ, хиты, характеристики и число извлечённых возможностей с сохранёнными техническими данными карточек. Проверены парсинг UTF-8 внутри слов, объекты без характеристик, переменные хиты и сохранение конфликтов. Повторное чтение JSON совпадает с построенным объектом. Изменения данных не подключают бестиарий к UI.
