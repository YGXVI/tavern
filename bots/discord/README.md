# Discord-бот «Распутья» — PoC записи (TASK-191)

Один бот в голосовом канале кампании. Сейчас умеет: подключаться к каналу, записывать с явного согласия каждого участника отдельные дорожки по Discord ID с таймкодами, ставить запись на паузу, переживать обычные разрывы связи и готовить WAV для будущей транскрипции.

Транскрипции, музыки, голосов NPC и звуковых эффектов пока нет — это следующие этапы.

## Требования

- Node.js **22.12 или новее** (`node --version`).
- ffmpeg в `PATH` — только для экспорта в WAV.
- Компьютер, на котором бот работает всю сессию. Записи лежат только на нём.

## Установка

1. **Тестовый Discord-сервер.** В Discord: «+» слева → «Создать мой». Включите режим разработчика: Настройки → Расширенные → «Режим разработчика».
2. **Приложение и бот.** https://discord.com/developers/applications → New Application. Вкладка **Bot** → Reset Token → скопируйте токен (никому не пересылайте). Привилегированные intents не нужны.
3. **Пригласите бота** (подставьте Application ID из General Information):
   `https://discord.com/oauth2/authorize?client_id=<APPLICATION_ID>&scope=bot%20applications.commands&permissions=68160512`
   Права: просмотр каналов, отправка сообщений, подключение к голосовому каналу, смена своего ника.
4. **Настройки.** В этой папке: скопируйте `.env.example` в `.env` и заполните `DISCORD_TOKEN`, `DISCORD_CLIENT_ID`, `DISCORD_GUILD_ID`, при желании `MASTER_USER_IDS`.
5. **Зависимости и команды:**
   ```sh
   cd bots/discord
   npm ci
   npm test
   npm run register   # /rec появится на тестовом сервере
   npm run doctor     # самопроверка: Node, .env, каталог записей, ffmpeg, токен, сервер, /rec
   npm start
   ```
   В консоли: `Бот … запущен. Записи: <каталог>`.

## Как пользоваться

| Команда | Кто | Что делает |
| --- | --- | --- |
| `/rec join` | мастер | бот входит в ваш голосовой канал |
| `/rec start` | мастер | запись начата; в канале появляются кнопки согласия |
| `/rec pause`, `/rec resume` | мастер | пауза и продолжение |
| `/rec stop` | мастер | остановка, итог в `summary.json` |
| `/rec leave` | мастер | бот выходит (запись останавливается) |
| `/rec status` | все | состояние, кто согласился |

Мастер — пользователь из `MASTER_USER_IDS`, обладатель роли `MASTER_ROLE_ID`, а если оба пусты — участник с правом «Управлять сервером».

**Согласие.** Голос пишется только у нажавших «Согласен на запись» — мастер тоже нажимает. «Не записывать меня» сразу закрывает дорожку. Новым участникам бот присылает напоминание. Во время записи ник бота — «🔴 Запись».

## Что получается

```
<RECORDINGS_DIR>/20261102-103000-<serverId>/
  manifest.jsonl          # события с таймкодами (мс от старта): участники, согласия, фрагменты, паузы, разрывы
  summary.json            # итог сессии
  <discordId>/00001.ogg   # фрагменты речи, Opus 48 кГц без перекодирования
```
По умолчанию `RECORDINGS_DIR` = `~/.rasputye-bots/recordings`; внутри репозитория бот его не примет.

Подготовка к транскрипции:
```sh
npm run export -- "<каталог сессии>"
```
Создаёт `wav/<discordId>/<seq>.wav` (16 кГц mono) и `segments.json` — фрагменты по времени, с именами участников.

## Живая проверка PoC

Только с согласия всех участников, на тестовом сервере. Результаты — комментарием в [#191](https://github.com/YGXVI/tavern/issues/191).

1. 2–3 человека, 60 минут, говорить по очереди и одновременно, одна пауза. Проверить: файлы у каждого, таймкоды в `segments.json` совпадают с ходом разговора.
2. Тот, кто не нажал согласие, — его папки нет.
3. Выключить Wi-Fi на 5–10 секунд у компьютера с ботом → в манифесте `connection_lost` и `connection_restored`, запись продолжилась.
4. 6–8 участников (люди или тестовые боты-«дикторы» из `TEST_SPEAKER_BOT_IDS`) и прогон 3–4 часа.

## Ограничения

- Приём голоса ботами Discord официально не документирует; обновление Discord может его сломать. Библиотека — `@discordjs/voice` 0.19 с поддержкой E2EE (DAVE).
- Таймкоды — по времени прихода пакетов (погрешность — десятки мс).
- Хранение 72 часа и автоудаление появятся вместе с транскрипцией; пока записи удаляются вручную.

## Разработка

`npm test` — тесты без сети (35): состояние записи, согласия, манифест, упаковка Ogg, сквозной прогон настоящего Opus → WAV (нужен ffmpeg с libopus, иначе тест пропускается), контроллер с подменой Discord, самопроверка.

`npm run doctor` печатает ✓/!/✗ по каждой проверке и, если бота нет на сервере, готовую ссылку-приглашение. Код возврата 1 — есть ошибки.
