# Распутье
Браузерный стол D&D 5e 2014 (демо без сервера). Запуск: `npm run dev`, затем http://localhost:4173. Проверки: `npm test`.

Сайт: https://rasputye.vercel.app. Обновляется сам: каждый commit в `main` с зелёными тестами выкатывается через GitHub Actions (`.github/workflows/deploy.yml`, нужен секрет `VERCEL_TOKEN`).

Работает (демо, всё хранится в браузере): вход «через Discord» — имитация с демо-аккаунтами; кампании, приглашения по ссылке и заявки; выбор или создание героя; стол мастера и игрока по макетам Figma — карта с камерой, сеткой, стенами и дверями, светом и тёмным зрением, туманом войны, местностью, слоем мастера (ловушки, метки, переходы между сценами), линейкой и шаблонами областей, рисованием и пингами; бой с инициативой, ходами, хитами, состояниями и спасбросками; кубы с лотком и журналом; базовый лист героя и статблоки существ SRD 5.1.

Как проверить «онлайн»: откройте кампанию «Склеп культа» под sol0139 (мастер), а во второй вкладке того же браузера — под Асей (игрок, Лира). Перемещения, броски, пинги и туман видны в обеих вкладках. Это имитация: другой компьютер кампанию не увидит, сервера и настоящей авторизации пока нет (DEC-008).

Прежний прототип с выбором роли и темами открыт по адресу `/legacy/`. Новый интерфейс его данные не читает и не стирает (DEC-011, [данные](docs/data.md)).

Дальнейшие этапы: полный лист героя (TASK-004), каталоги заклинаний и предметов в интерфейсе, сервер кампаний с настоящим входом, аудиозапись и транскрибация, войсченджер.

## Темы
Новый стол — одна тёмная тема из макетов. Каталог тем «Оформление» (Полночь, Пергамент, Графит, Бордовое вино) остался в прототипе `/legacy/`.

## Вход и роли
Вход — имитация экрана Discord: выбирается демо-аккаунт или вводится ник, у каждой вкладки свой человек. Роль мастера или игрока берётся из членства в конкретной кампании. Мастер ведёт сцену и видит всё; игрок двигает своего героя и видит то, что видит отряд. Это разделение интерфейса, а не защита: все данные кампании лежат в localStorage браузера. Перед совместной игрой по сети нужны серверные учётные записи, членство и права.
