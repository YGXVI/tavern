# Демонстрационные справочники

## Purpose

Базовое поведение GitHub main после TASK-007 / DEC-011 (2026-10-29). Ниже нормативные требования текущей версии. Дополнительный контекст сохраняет прежние планы и ограничения; его целевые разделы не означают готовность.

## Requirements

### Requirement: Демонстрационные справочники

Приложение SHALL предоставлять встроенный бестиарий нового стола; прежний краткий справочник доступен в /legacy/. Каталоги TASK-006/008 не считаются подключёнными до интеграции соответствующего кода.

#### Scenario: Базовый сценарий

- **WHEN** мастер открывает бестиарий нового стола
- **THEN** он видит встроенные записи существ и может выбрать существо для сцены

## Контекст, ограничения и будущие этапы

Материал прежнего `docs/features/library.md` перенесён без потери целей. Описания старого прототипа относятся к `/legacy/`. При устаревшем описании текущего состояния ориентироваться на Requirements выше и код; изменение требований оформлять delta spec.

# Библиотека правил, существ и предметов

## Статус

Стартовый справочник, не полный каталог. Ответственный — через [../status.md](../../../docs/status.md).

## Сейчас

Новый стол: `dist/js/data/bestiary.js` и `dist/js/views/table/p-side.js` — поиск существ и добавление токенов. Прежний справочник ниже относится только к `/legacy/`.

`library[]` и `renderLibrary()` в `dist/legacy/app.js`; `#search`, `#filters`, `#libraryCards` в `dist/legacy/index.html`. Шесть встроенных записей: четыре кратких описания механик, гоблин и факел. Поиск по заголовку/тексту, фильтры `all`, `rule`, `monster`, `item`. Нет внешней базы, редактирования, импорта, полного каталога артефактов или связанного создания токена из бестиария.

## Целевая версия

Поиск правил D&D 5e 2014, бестиария и снаряжения; домашний контент мастера с отдельной областью видимости. Контент должен иметь ID, тип, редакцию, источник и сведения о праве использования. Не копировать закрытые книги и базы по факту наличия доступа к ним.

## Критерии следующего этапа

- Согласовать источник и структуру записей до массового наполнения.
- Отличать проверенный источник от домашней записи; фильтр редакции не смешивает 2014 и другие правила.
- Пустой результат и ошибка загрузки показываются корректно.
- Создание токена из существа копирует нужные боевые данные и сохраняет ссылку на запись по ID.
- Каталог предметов связывается с инвентарём без превращения экземпляра предмета в общую запись каталога.

## Общие файлы

Пока контент встроен в `app.js`, редактирование каталога пересекается почти со всеми функциями. Вынос в отдельный модуль можно сделать отдельной небольшой задачей, сохранив текущий UI.
