## Why

Решение Яры (03.11.2026): войсченджер мастера работает так — **сайт управляет пресетами, браузер получает и обрабатывает голос мастера, Discord-бот передаёт изменённый голос участникам.** Отдельное локальное приложение и виртуальный микрофон не нужны. План A (#121, LiveKit) отменён 02.11; голосовая платформа — Discord, один бот в `bots/` (#191). DSP Voice Changer — этап дорожной карты #191 после транскрипции и DJ; этот change готовит его контракт заранее, чтобы `bots/` и сайт не разошлись.

Главный риск — одновременное звучание оригинального и изменённого голоса мастера. Второй — потеря исходной речи мастера для транскрипции: при серверном мьюте Discord не передаёт его звук, а PoC записи #191 пишет только входящий голос.

## What Changes

- **Мост «браузер → бот»**: WebSocket (WSS), бинарные кадры Opus 20 мс, JSON-сообщения управления в том же соединении; версия протокола в рукопожатии.
- **Привязка мастера без новой схемы БД**: одноразовый код из команды бота в Discord вводится на сайте; Discord ID мастера бот знает из самой команды.
- **NPC-режим как машина состояний бота** с подтверждённым серверным мьютом, lease, grace-периодом и владением мьютом, переживающим перезапуск бота.
- **Уважение чужих ограничений**: `self_mute`/`self_deaf` останавливают воспроизведение; бот не ставит мьют поверх существующего и не снимает чужой; внешний анмьют во время режима немедленно останавливает воспроизведение.
- **Обработка в браузере**: AudioWorklet DSP с пресетами, предпрослушивание, кнопка «Обычный голос»; измерение задержки по участкам, видимое мастеру.
- **Подготовка транскрипции**: при активной записи #191 и согласии мастера — второй, исходный поток только для записи; события `npc_on`/`npc_off` в манифесте записи для подписи «Мастер (как <NPC>)».

## Capabilities

### Modified Capabilities

- `voice-changer`: добавлены требования моста, NPC-режима, мьюта, отказоустойчивости, задержки и исходного потока. Существующее требование «Граница войсченджера» сохраняется до приёмки рабочего прототипа и заменяется при архивации этого change.

### New Capabilities

Нет. Транскрипция (STT, разделение участников, таймкоды, экспорт TXT, хранение и удаление) — следующий change; здесь только данные, которые для неё нужны.

## Зависимости и контракты

- **`bots/` (Dezmondy)**: модуль `voice/` (приём моста, воспроизведение, машина состояний), `selfMute:false` при NPC-режиме, новые права, второй источник аудио мастера и события в манифест записи, будущее микширование с DJ. Внутреннюю реализацию предлагает и ведёт Dezmondy; этот change фиксирует только внешний контракт и наблюдаемое поведение. Существующий PoC записи не переделывается.
- **Интерфейс (sol0139)**: подключение панели к столу — `dist/js/views/table/index.js` (mount/unmount), `chrome.js` (кнопка). Новые файлы сайта — `dist/js/audio/**`, `dist/css/audio.css`; `dist/index.html` — подключение CSS.
- **Без новых npm-зависимостей сайта**: Web Audio, AudioWorklet, WebCodecs, WebSocket — встроенные API браузера.
- **Инфраструктура (Яра + Dezmondy)**: где работает бот и как до него доходит браузер мастера по `wss://` — открытый вопрос, см. design.md.

## Не входит

STT-движок, разделение участников, экспорт TXT, хранение и удаление записей (следующий change); DJ и soundboard; клонирование реальных голосов; захват системного звука; изменения PoC записи сверх согласованного второго источника и событий манифеста.
