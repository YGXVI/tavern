## Why

Сейчас «онлайн» — только вкладки одного браузера: друг по ссылке-приглашению на своём компьютере видит «Приглашение недействительно», а скрытые мастером токены, ловушки и заметки лежат в localStorage игрока. Чтобы сыграть первую настоящую сессию, нужны сервер, настоящий вход и права, которые проверяет сервер, а не интерфейс. DEC-008 открыт с начала проекта; интерфейс TASK-007 уже собран вокруг двух точек (`store.js` и шина событий), поэтому сервер можно подключить, не переписывая экраны.

## What Changes

- **Решение DEC-013 (закрывает DEC-008):** Supabase — Postgres с правилами доступа (RLS), Supabase Auth с провайдером Discord, Realtime (изменения таблиц, Broadcast, Presence), Storage для карт. Отдельная бесплатная организация Supabase `rasputye` с проектом `tavern` и отдельное приложение Discord «Распутье»: ничего общего с DnD Kids (`dnd-novice`) — ни организации, ни пользователей, ни ключей, ни хранилища; проект `dnd-novice` не изменяется. Своего сервера нет; браузер говорит с Supabase через `@supabase/supabase-js`, подключённый ES-модулем с CDN с закреплённой версией (сборщик не вводится, DEC-002).
- **Настоящий вход через Discord.** Экран входа остаётся тем же; кнопка ведёт в Discord OAuth через Supabase. Профиль: ник и аватар из Discord. Выход, восстановление сессии после перезагрузки.
- **Серверные кампании.** Создание, список «Веду / Играю», приглашение по коду/ссылке со сроком и ручным одобрением, заявки, выбор или создание героя, уход и исключение — через сервер; вход по коду идёт функцией базы, которая не раскрывает кампанию до вступления.
- **Стол онлайн.** Сцены, токены, листы, бой, журнал и запросы спасбросков хранятся в Postgres; изменения приходят остальным участникам в реальном времени. Мгновенные события (перетаскивание, линейка, шаблон, пинг, «смотрите сюда», тосты бросков) идут через Broadcast, «в сети» — через Presence, на приватных каналах кампании.
- **Права на сервере.** Роль берётся из членства в кампании. Игрок не получает скрытые токены, ловушки, заметки мастера и чужие скрытые броски; меняет только своего героя, свой токен и разрешённые поля боя (своя инициатива, конец своего хода, результат своего спасброска). Остальное — мастер.
- **Карты** серверной кампании загружаются в Storage кампании вместо IndexedDB.
- **Песочница.** Нынешний локальный режим остаётся как «Попробовать без входа»: демо-аккаунты, `rasputye-v2-*` в браузере, без сервера. Данные песочницы на сервер не переносятся. **BREAKING для локальной демо-кампании нет:** ключи и формат не меняются.

## Capabilities

### New Capabilities
- `campaign-access`: роли по членству, серверные права и скрытые данные мастера; что игрок может читать и менять.
- `table-sync`: доставка изменений стола участникам, мгновенные события, присутствие, поведение при обрыве связи и конфликтах.

### Modified Capabilities
- `auth`: к локальному демо-входу добавляется настоящий вход через Discord; демо-вход становится песочницей.
- `campaigns`: к локальным кампаниям добавляются серверные кампании, приглашения и членство между устройствами.
- `maps`: карты и данные сцены серверной кампании хранятся на сервере; скрытие данных мастера становится серверным.

## Вне объёма

Строгий туман на сервере: игрок получает стены, свет и всех существ, которых мастер не скрыл, а обзор и туман считаются у него в браузере. Перенос песочницы на сервер. Платный тариф. Роли сверх «мастер/игрок» (со-мастер, зритель). Каталоги заклинаний и предметов в интерфейсе (TASK-006/008/009). Полный лист героя (TASK-004). Своя серверная логика вне функций Postgres.

## Impact

Сайт перестаёт быть полностью статическим по данным: появляется внешний сервис и его ограничения (бесплатный проект засыпает после недели без активности; 500 МБ базы, 1 ГБ файлов, 200 одновременных подключений, 2 млн сообщений Realtime в месяц). Публичный ключ проекта (publishable) появляется в `dist/` — это допустимо только вместе с RLS; служебный ключ (service role) в браузер и Git не попадает. Откат: флаг режима в `dist/js/server/config.js` возвращает приложение к песочнице без удаления серверных данных.
