# Spec Delta

## ADDED Requirements

### Requirement: Атомарное создание из предложения конструктора
Character SHALL создаваться единственным подтверждаемым серверным путём. Сервер MUST проверить caller, кампанию, владельца, политику, ревизии определений и обязательные выборы, не доверяя клиентскому valid. Отказ MUST NOT оставлять частичный лист, членство или токен.

#### Scenario: Подмена владельца или недоступный выбор
- **WHEN** запрос содержит чужого owner, неизвестный источник или подкласс раньше уровня класса
- **THEN** сервер отклоняет запрос и не создаёт Character

#### Scenario: Политика изменилась после предпросмотра
- **WHEN** серверная ревизия политики отличается от предпросмотра
- **THEN** создание требует актуального контекста и повторной проверки, без тихой подмены выбора

### Requirement: Идемпотентность создания
Операция создания SHALL иметь устойчивый operationId и Character ID до первого запроса. Повтор того же запроса MUST возвращать подтверждение одного результата; повтор operationId с другим payload MUST быть отклонён. Исторический ACK MUST NOT заменять более новый лист устаревшим снимком.

#### Scenario: Ответ потерян
- **WHEN** сервер сохранил героя, а клиент не получил ACK и повторил запрос
- **THEN** второго героя/повторных grants не возникает и клиент получает подтверждённый результат операции

### Requirement: Совместимость происхождения и ручных значений
Созданный герой SHALL использовать канонический Character TASK004, сохранять ссылки и ревизии источников и отделять рассчитанное от явно подтверждённого ручного значения. Обновление справочника MUST NOT менять сохранённого героя автоматически. Существующие герои MUST открываться без миграции с потерей полей.

#### Scenario: Новая версия определения
- **WHEN** каталог обновился после создания
- **THEN** герой сохраняет применённый снимок и происхождение, изменение возможно только отдельной подтверждённой операцией

#### Scenario: Мастерское исключение
- **WHEN** мастер явно разрешает значение вне поддержанной канонической сборки
- **THEN** причина и override сохраняются, а UI не обозначает такую сборку автоматически проверенной по всем правилам
