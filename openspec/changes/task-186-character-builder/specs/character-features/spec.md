# Spec Delta

## ADDED Requirements

### Requirement: Особенности предысторий и адресация получения
Публичный каталог SHALL поддерживать особенности предысторий SRD с проверенными background refs и source spans. Определения сборки SHALL ссылаться на прежние feature IDs; уровень/количество получения задаются отдельным проверенным правилом, а не догадкой из null или имени.

#### Scenario: Особенность Acolyte
- **WHEN** поддержана предыстория Acolyte
- **THEN** её особенность имеет отдельный устойчивый ID и ссылку на SRD61, а конструктор получает её по ссылке без копирования справочной записи

#### Scenario: Одноимённые способности
- **WHEN** две области содержат одноимённое правило
- **THEN** исходные ID/родители сохраняются, а привязка к получению ссылается на нужную область

### Requirement: Разделение публичных определений и личных шаблонов
Расширение публичного каталога SHALL валидировать новые типы и связи явно. Оно MUST NOT автоматически расширять допустимые виды личных шаблонов, права или публичный кэш. Личная запись без проверенного механического определения MUST NOT считаться допустимым правилом сборки.

#### Scenario: Публичный тип не поддержан private API
- **WHEN** клиент отправляет новый публичный тип через прежний private endpoint
- **THEN** сервер отклоняет его до согласованного расширения private-контракта, а публичный loader не принимает личные данные
