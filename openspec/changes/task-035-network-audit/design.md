# Design

## Контекст и подход

Аудит связывает два точных SHA: main с локальным store и серверный preview main после PR #58. Доказательства маркируются: эксперимент VM, статический вывод, непроверенный реальный сценарий. VM читает исходный store без изменений и использует только синтетическую базу; это не эмуляция Supabase или браузерной приёмки.

## Контракты и владение

Продуктовые API/DOM/localStorage/SQL сохраняются. Один автор — своя папка change и новый отчёт; общий store и серверная реализация остаются в TASK-002. Согласование требуется до любого исправления. Аудит не назначает коллегу проверяющим без его согласия.

## Проверка

Проверить ссылки и наличие упомянутых файлов в соответствующем SHA, OpenSpec current/archive, npm test. Фактические сетевые/UI-прогоны заносятся отдельно с результатом и условиями. Отсутствие Chromium/аккаунтов/прогона отражается явно. В отчёт не входят ключи, raw network dumps и закрытые пользовательские данные.

## Ограничения, миграция и откат

Live Supabase не открывался; утверждения коллег о применении миграций не становятся результатами этого аудита. Публикация ветки и Issue не доказывает merge/deploy или согласование. Нет изменения данных и миграции; откат документов обычным revert. План остаётся активным до подтверждения другим участником; архивация не имитируется.
