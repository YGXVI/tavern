# Design

Модель следует Creature из подтверждённого TASK-097. normalizeCreature(input) возвращает глубокую копию с пустыми строками, массивами и null для отсутствующих чисел. Она не выдаёт новый ID, владельца или время и не исправляет ошибочные типы. Неизвестные JSON-поля сохраняются; не-JSON значения, циклы и объекты с прототипом отклоняются валидатором.

validateCreature(input) возвращает `{valid, errors:[{path,code,message}], bytes}`. Обязательны id, ownerId, непустое name, source manual/image; изображение обязательно для source=image. Составные поля проверяются независимо, save требует who target/self. Отсутствующие числовые статы допустимы как null, включая картинки и неполные ручные записи. Это не готовность к автоматическому бою. Лимит — 65536 байт JSON нормализованной записи в UTF-8.

fromSrd(monster, {id,ownerId,updatedAt}) принимает исходную запись со stat_block.source=srd_api_2014 или runtime-запись с srd=true. Возвращает черновик с source=manual; новые id/owner задаёт вызывающий клиент. provenance сохраняет исходный ID, источник, атрибуцию и ссылку CC BY 4.0. Полный каталог хранит больше технических полей, чем runtime: неописанные моделью поля и условия сохраняются в записи/возможностях с исходными ключами. Из raw saving_throw не угадывается who: сырой спасбросок сохраняется, типизированное save заполняет человек. Карточки других источников не принимаются. Ручные стартовые записи без явного srd-маркера не считаются подтверждённым входом этого адаптера. Копирование runtime сохраняет только действительно доступные в runtime поля: потерянные генератором детали восстановить по тексту не пытается.

toMonster(creature) возвращает отдельную совместимую runtime-запись с id lib:<id>. Все компоненты урона, save и дополнительные параметры доступны в возможностях; простое поле damage для старой кнопки броска заполняется только для одного известного безальтернативного компонента. Сумма или первый компонент составного урона не выдаются за весь урон. Неподдержанное остаётся текстом и структурой. Строки traits runtime преобразуются в name/text. Реестр monsterById не изменяется; регистрацию делает Claude при подключении интерфейса.

Снимок campaign_creatures может иметь owner_id=null для статблока только мастера. toMonster проверяет поля отображения без обязательного ownerId и удаляет его из проекции; владельца не придумывает. validateCreature для сохранения личного шаблона по-прежнему требует владельца. Это не выдача доступа: RLS/выбор видимого снимка остаётся у вызывающей стороны.

Миграций нет. Откат — revert порции. Данные не сохраняются, публичная база и игровые действия не меняются. Проверка: все 334 исходные SRD и 322 runtime, Unicode/лимиты, self/target, альтернативы, копирование без мутаций и ошибки типов. UI/серверные проверки здесь неприменимы.
