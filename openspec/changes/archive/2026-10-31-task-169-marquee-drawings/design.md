# Design

## Что берёт рамка

- Токены — как раньше: центр внутри рамки, видимый мастеру.
- Рисунки — «касается» (правило Figma): вершина внутри рамки или отрезок пересекает её край. Для надписи — пересечение её прямоугольника (`getBBox` узла) с рамкой. Рамка целиком внутри большой фигуры фигуру не берёт: иначе любая рамка внутри сферы заклинания хватала бы и сферу.
- Только рисунки, которые пользователь может править (`canEditDrawing`): мастеру — все. Рамка доступна только мастеру (инструмент «Выделение» и Shift в режиме мастера), Shift+клик по своим рисункам — и игроку.

## Состояние

- `ctx.ui.selDrawing` (одиночный рисунок с панелью) остаётся как есть.
- Новый `ctx.ui.selDrawings: Set` — рисунки группы. Группа существует вместе с `ctx.ui.selection` (токены). Если рамка дала ровно один рисунок и ни одного токена — включается одиночное выделение `selDrawing`.
- `ctx.select(ids)` снимает и одиночный рисунок, и группу; опция `{ keepDrawings: true }` (Shift+клик по токену) группу оставляет.
- Набор живёт только во вкладке; другим участникам не уходит (TASK-164 показывает чужое выделение токенов).

## Перетаскивание

- За токен группы: прежний `dragTokens` (привязка, стены, путь); рисунки группы едут на сдвиг ведущего токена (`ui.drawMove = { ids, dx, dy }`). При записи сдвиг берётся по итоговому ходу ведущего.
- За рисунок группы: сдвиг курсора; если в группе есть токены — округляется до целых клеток для всех (фишки остаются в клетках, взаимное расположение сохраняется), токены — по `ctx.dragging` без проверки стен (мастерская расстановка, как Alt), в пределах карты; закреплённые и чужие токены не едут.
- Запись одна: `commitMoves(ctx, moves, cost, { ids, dx, dy })` — токены и рисунки в одном `mutateScene` с отменой и повтором. Сцена до записи не правится — серверная разница видна (TASK-166).

## Удаление

- `deleteTokens(ctx, ids, drawIds)` — прежнее подтверждение для героя, затем токены, записи боя и рисунки в одном `mutateScene`. Игроку токены группы не удаляются, только его рисунки.
