# Design

creatures(id text PK, owner_id UUID, data JSONB, updated_at). data — Creature без id/ownerId/updatedAt, эти поля восстанавливаются из колонок. Только владелец читает/изменяет. Идентичность неизменна. Внутренний счётчик владельца изменяется AFTER INSERT/DELETE одной транзакцией; ограничение 500 выдерживает одновременные вставки, upsert существующей строки не расходует квоту. Счётчик недоступен API. CHECK ограничивает UTF-8 представление data::text 65536 байт; PostgreSQL добавляет пробелы при сериализации JSONB, поэтому пограничный клиентский размер может быть отклонён сервером с явной ошибкой. Оба ограничения — верхние, данные не обрезаются.

campaign_creatures(campaign_id,id,owner_id nullable,data,source_id nullable,updated_at) — самостоятельный снимок. Нет FK к личному шаблону: его удаление не удаляет копии кампании. Мастер всё; активный игрок читает/создаёт только свои копии призывов; не обновляет и не удаляет снимки. После исключения доступа нет. Функция постановки и привязка токенов — у Claude.

library — приватный bucket, путь <uid>/<uuid>.<ext>, 5 MiB, PNG/JPEG/WebP. Клиент проверяет MIME/размер/сигнатуру; bucket повторяет размер/MIME. RLS проверяет владельца первого сегмента для чтения/вставки/удаления/обновления, включая новый путь. Стабильная ссылка library:<path>; временный signed URL не хранится в Creature и не кэшируется между пользователями. Копирование изображения в кампанию — часть place_creature Claude, не раздача всей библиотеки.

core API создаётся через createLibrary с адаптером контекста; готовые listCreatures/saveCreature/deleteCreature/copySrdCreature/uploadLibraryImage/resolveLibraryImage используют текущий auth/store только при вызове. Песочница читает свежий rasputye-v2-db и пишет только creatures, сохраняет кампании и версию; ошибки записи пробрасываются. Данные сервера не проходят через store и не попадают в песочницу. Каждый async-ответ проверяет неизменность пользователя/режима до возврата. Нет долгоживущего кэша личных данных.

Миграции только добавляют. Откат — revert кода; удаление наполненных таблиц отдельным решением. Проверка RLS на локальном PostgreSQL с явными заглушками auth/storage — не эквивалент production Storage API; живые uploads и браузерный UI ожидают интеграцию Claude. Дополнительно клиентские тесты ошибок, смены пользователя и независимых копий.

Источники технических ограничений: https://supabase.com/docs/guides/storage/buckets/fundamentals и https://www.postgresql.org/docs/14/plpgsql-trigger.html . Не вводится новый источник игрового контента.
