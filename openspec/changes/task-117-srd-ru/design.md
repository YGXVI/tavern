# Проектирование русского слоя SRD

Это конкретное предложение контракта для человеческого подтверждения; файлы переводов и runtime пока не созданы/изменены.

## Проверенная база

`main` 1945eed2f0e212488fdf13df53b44e2411cd0ddd содержит 334 записи с `stat_block.source === 'srd_api_2014'`. У остальных 2572 записей `stat_block` отсутствует. Четыре раздела дают 1503 описания, 263615 символов, 1113 уникальных EN-текстов. В рекурсивно проверенных ключах SRD-статблоков не найдено отдельного поля вводной прозы легендарных действий. Её не нужно сочинять или брать из другого перевода.

SHA-256 файла `data/bestiary/bestiary-2014.json`: `7e072fe37b6bef680b29c0e1fbad8ac2e235b154ffc26e7475cc62630931a3f5`. Этот хеш документирует базу; при обновлении каталога проверяется отдельно каждый перевод, а не только хеш всего файла.

## Контракт srd-ru.json

Предлагаемая форма (пример лишь поясняет контракт, не считается готовым переводом корпуса):

```json
{
  "schema_version": 1,
  "language": "ru",
  "source": {
    "path": "data/bestiary/bestiary-2014.json",
    "base_commit": "1945eed2f0e212488fdf13df53b44e2411cd0ddd",
    "stat_block_source": "srd_api_2014",
    "license": "CC-BY-4.0"
  },
  "monsters": {
    "dndsu:monster:100": {
      "special_abilities": {
        "Amphibious": {
          "999f0213e00940a5aa11a5c77c4d731056f65d30806bceeda1badd74b890b611": {
            "ru": "Дракон может дышать воздухом и под водой."
          }
        }
      }
    }
  }
}
```

Пример EN: `The dragon can breathe air and water.` Хеш вычисляется из UTF-8 этой строки без trim, смены переносов и нормализации Unicode. Ключ верхнего уровня — исходный `monsters[].id`, а не runtime `srd:<slug>` и не русское имя.

Разделы: `special_abilities`, `actions`, `legendary_actions`, `reactions`. `name_en` является точным отдельным ключом, хеш — следующим ключом: конкатенация через потенциально неоднозначный разделитель не нужна. Одинаковые имя и EN внутри одного раздела могут ссылаться на один перевод; покрытие считается по исходным вхождениям, не по числу словарных листьев. Одинаковое название с разным EN требует разных хешей.

Отсутствие текущего имени/хеша, пустой ru, лишний ID или старый хеш — ошибка проверки. Для изменения оригинала нужен новый перевод с новым хешем; незаметно подставлять устаревший перевод нельзя. Генератор проверяет весь файл до записи выхода; ошибка не должна повреждать существующий модуль. Старые хеши сохраняет Git, в рабочем JSON остаются текущие ключи.

Если будущая версия SRD добавит вводную прозу легендарных действий, обнаружение нового поля останавливает проверку полноты. После подтверждения точного EN-пути он добавляется в явный реестр и отдельный раздел `legendary_intro`; отсутствие поля не заполняется общим придуманным правилом. Текущий объём — ровно 1503 вхождения.

## Словарь до перевода

Предлагается `srd-ru-glossary.json` с `schema_version`, `sources`, `terms`, `allowed_latin`, `style` и `decisions`. У термина — `en`, `ru`, допустимые русские грамматические формы, запрещённые конкурирующие варианты, ссылки/путь и место источника. Для расхождения — варианты и обоснование выбора. Список `allowed_latin` начинается пустым и расширяется лишь для реально необходимых обозначений с обоснованием, не для обхода проверки.

Приоритет согласованности: действующие имена существ/способностей в генераторе и русские названия заклинаний из `data/spells/spells-2014.json`; состояния — `CONDITIONS` в `dist/js/data/rules.js`. Терминологию сверяем с официальным глоссарием Hobby World для 5e и словарём dnd.su версии 2014. Ссылки и результаты сверки фиксируются для каждого спорного термина; редакция 2024 не подменяет 2014. Копировать большие словари целиком или чужие предложения не требуется.

Известные места для сверки: `Armor Class` (КБ/КД), `Spellcasting` (колдовство/использование заклинаний), `Innate Spellcasting` (врождённое колдовство/врождённое использование заклинаний), `long rest` (долгий/продолжительный отдых), `necrotic damage` (некротический урон/урон некротической энергией). До сверки эти варианты не объявляются подтверждённым каноном. Имена и подписи существующего runtime не переименовываются попутно.

Формат прозы: `2к6`, `фт.`, `Сл`, полные названия характеристик; состояния склоняются. Техническая формула `damage: '2d6+8'` остаётся без изменений. Не заменять необходимые условия общим пересказом: субъект спасброска, повторные попытки, окончание эффекта, ограничения целей и использование действий должны оставаться точными.

## Генерация и совместимость с #107/#116

Текущий генератор выбирает любую ненулевую запись. После #107 этого недостаточно: там ненулевых записей 2906. SRD-срез определяется **явно** через `stat_block.source === 'srd_api_2014'`, не через имя, наличие английской строки или префикс ID.

В #116 уже предложен такой фильтр. Перед изменением `tools/bestiary-srd.mjs` согласуется его автор: если он уже интегрирован другой задачей, переиспользуется; если назначен TASK-117 — добавляется здесь одной правкой и тестом на примесь не-SRD. До передачи не вести параллельное редактирование этого участка. Чужую source-ветку не мержить в нашу ради проверки: достаточно временного входа вне отслеживаемых файлов либо синтетической не-SRD записи в тесте.

Все 334 исходные записи переводятся. В runtime прежний HAND исключает 12, остаётся 322. Для каждого текущего объекта особенностей, действий, реакций и легендарных действий добавляется **только `ru`**. `desc`, `name`, `en`, ID, числовые поля, формулы, лимиты, порядок списков, наличие полей и английская проза сохраняются. Удаление новых полей `ru` из результата должно дать структурное равенство исходному модулю. У 13 стартовых существ в `bestiary.js` ничего не меняется.

Предлагаемый JSON не загружается браузером: генератор встраивает ru в существующий модуль. Новый интерфейс и переключатель языка не создаются. `sheet.js` продолжает читать desc. Старые тесты английского desc остаются верными, их не нужно ослаблять или переписывать под русский.

## Проверки

`tests/bestiary-srd-ru.test.js` должен проверять:

1. 334 SRD-записи и 1503 непустых description_en покрыты по имени и точному SHA-256; в том числе все HAND. Учитываются вхождения и дубликаты, обнаруживаются лишние/устаревшие переводы.
2. Положительные и отрицательные случаи: изменённый EN, отсутствующий/пустой ru, переставленные записи, дубли имени с разным текстом, лишний ключ, примесь не-SRD. Тест не должен писать в отслеживаемые файлы.
3. Совпадение чисел и кубов после разрешённых преобразований d→к, пробелов в формуле, записи тысяч, русских порядковых форм. Отдельные проверки связывают Сл со спасброском, дистанцию с единицей, бонус со знаком. Числительные словами, дроби и единицы вне футов учитываются явно; не добавлять исключения без пояснения конкретного текста.
4. Русский текст не содержит непредусмотренной латиницы; термины проверяются с разрешёнными грамматическими формами. Regex не доказывает смысловую эквивалентность: субъект, отрицание, условия и порядок эффекта сверяются человеком/редактором по оригиналу.
5. 322 runtime-записи, EN и механические поля неизменны; повторная генерация побайтно совпадает. Ошибка хеша не меняет выход.

20 пар EN/RU выбираются детерминированно по ID, разделу и исходному имени: рукопашная и дальнобойная атака, составной урон, спасбросок, захват, перезарядка, заклинания, врождённое колдовство, легендарное действие, реакция, условное окончание эффекта. Подбор должен включать длинные и сложные описания, не только шаблонные атаки. В отчёте — ссылки на исходную запись, SHA-256, полный EN, полный самостоятельный RU и результат сверки.

Обязательные команды: `npm ci`, `npm test`, `npm run spec:validate`, `npm run spec:validate:archive`, `node --check` изменённых JS. Статические проверки и исходные тесты плана не выдаются за проверку ещё не существующего перевода.

## Размер, выпуск и откат

База модуля: **559472 UTF-8 байта / 90364 gzip-9 байта** (`mtime=0`). После перевода измеряются тем же способом абсолютный размер, прирост в байтах и процентах. Размер будущего RU по EN не угадывается. До измерения прирост неизвестен.

Коммиты: план; словарь и проверки; переводы партиями по русскому имени с ID как вторым ключом; итоговая генерация и отчёт. Неполные партии явно обозначаются в Issue и не публикуются в main. Завершённый change синхронизируется/архивируется только после реализации и проверок. Снимок и итоговый PR — после проверки свободного интеграционного PR направления и свежего main.

Откат runtime — обычный revert согласованного коммита: прежний desc не менялся, миграций и удаления данных нет. Отдельные файлы переводов можно сохранить для дальнейшей редакторской работы. UI, источники PR #107 и его лицензии этим планом не принимаются.
