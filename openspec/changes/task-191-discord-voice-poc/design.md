# Design: Discord Voice PoC

## Context

TASK-191 / [#191](https://github.com/YGXVI/tavern/issues/191). Решение Яры 02.11: один Discord-бот в monorepo-подсистеме `bots/`, первым — PoC записи. Всё работает на одном ПК; распределённой инфраструктуры, платных сервисов и интеграции с сайтом нет.

Исследование 02.11.2026:
- С начала марта 2026 звонки Discord (кроме Stage) идут с E2EE по протоколу DAVE; бот обязан его поддерживать. Голосовой шлюз v8, транспорт `aead_xchacha20_poly1305_rtpsize` обязателен.
- Приём голоса ботами Discord официально не документирует — стабильность не гарантирована; это главный риск.
- `@discordjs/voice` 0.19.2 (Node ≥ 22.12) после транспортной расшифровки вызывает DAVE-расшифровку для каждого userId (`VoiceReceiver.parsePacket`), поэтому дорожки по Discord ID доступны. Стек совпадает с проектом (JS, ES-модули).
- Облачная песочница Claude не достигает Discord: живые проверки — только на локальном ПК.

## Goals / Non-Goals

Цель: воспроизводимый раздельный приём 6–8 участников с таймкодами, согласием и устойчивостью к обычным сбоям в многочасовой сессии.

Не входят: транскрипция, DJ, DSP, soundboard, микшер исходящего звука, интеграция с сайтом/Supabase, хранение в облаке, CI-джоб, продакшен-приложение Discord.

## Decisions

### Структура

```
bots/
  README.md
  discord/
    package.json, package-lock.json, .env.example, .gitignore, README.md
    src/index.js                 # запуск: клиент, обработчики
    src/config.js                # настройки из окружения
    src/core/commands.js         # slash-команда /rec и кнопки согласия
    src/core/permissions.js      # кто мастер
    src/core/voice.js            # подключение, переподключение
    src/recorder/session.js      # состояние записи и согласия (без сети)
    src/recorder/manifest.js     # манифест JSONL
    src/recorder/tracks.js       # приём Opus → Ogg по сегментам
    src/recorder/export.js       # индекс сегментов и WAV 16 кГц
    src/util/time.js
    scripts/register-commands.js, scripts/export-session.js
    tests/*.test.js              # node --test без сети
```
Остальные модули (`transcription/`, `dj/`, `voice/`, `soundboard/`, `shared/`) появятся со своим кодом. Один процесс, одно Discord-приложение.

### Управление и права

Одна команда `/rec` с подкомандами `join`, `leave`, `start`, `pause`, `resume`, `stop`, `status`. Управляет мастер: пользователь из `MASTER_USER_IDS`, обладатель роли `MASTER_ROLE_ID` или, если ни то ни другое не задано, участник с правом Manage Server. `status` доступен всем.

### Согласие и видимость

- `start` публикует в текстовом канале сообщение о записи с кнопками «Согласен на запись» и «Не записывать меня». Пишутся только согласившиеся; отказ или отзыв останавливает и закрывает дорожку этого участника.
- Участник, вошедший во время записи без согласия, не записывается; бот публикует ему напоминание.
- Согласие действует до конца сессии записи; новая `start` требует нового согласия.
- Во время записи ник бота — «🔴 Запись» (если есть право Change Nickname), в канале сообщения о старте, паузе, возобновлении и остановке. Скрытой записи нет: без активной сессии приёмник не подписывается.

### Дорожки и таймкоды

- Discord не шлёт пакеты в тишине. Бот подписывается на участника по событию начала речи (`EndBehaviorType.AfterSilence`, 1 с) и пишет каждый фрагмент речи отдельным файлом `<discordId>/<seq>.ogg` без перекодирования (`prism-media` `OggLogicalBitstream`, 48 кГц stereo).
- Время — монотонные часы процесса от старта сессии плюс UTC старта. Паузы не вычитаются: таймкод — реальное время сессии.
- Манифест `manifest.jsonl` — построчные события: `session_start`, `participant` (ID, имя, ник), `consent`, `voice_join`/`voice_leave`, `segment_start`/`segment_end` (файл, смещения, пакеты), `pause`/`resume`, `connection_lost`/`connection_restored`, `error`, `session_stop`. Построчная запись переживает падение процесса.
- Каталог записей задаётся `RECORDINGS_DIR`, по умолчанию `~/.rasputye-bots/recordings` — вне репозитория.

### Устойчивость

- При `Disconnected` бот ждёт до 5 с перехода в `Signalling`/`Connecting` (обычный переход между серверами Discord), иначе пробует подключиться заново до 5 раз с паузой; каждый разрыв и восстановление отмечаются в манифесте. Открытые фрагменты закрываются при разрыве.
- Ошибка одного фрагмента не останавливает запись остальных.
- Остановка процесса (SIGINT/SIGTERM) завершает сессию и закрывает файлы.

### Подготовка к транскрипции

`npm run export -- <каталог сессии>` строит `segments.json` (участник, файл, начало и конец в мс) и конвертирует каждый фрагмент в WAV 16 кГц mono через ffmpeg. Транскрипция — следующий change.

## Risks / Trade-offs

- Приём не документирован Discord → проверить на свежем тестовом сервере до расширения; при поломке — обновление `@discordjs/voice`.
- DAVE-переходы при входе/выходе участников могут давать краткие ошибки расшифровки → библиотека их терпит; потерянные пакеты не выдаются за речь.
- Нагрузка 6–8 участников: файлы без перекодирования, CPU минимален.
- Таймкоды фрагментов зависят от времени прихода пакетов (сетевой джиттер десятки мс) — достаточно для транскрипта.

## Migration Plan

Только новые файлы и строка реестра. Откат — revert; записи на ПК удаляются вручную по политике следующего этапа (72 ч — в change транскрипции).

## Проверки

- Юнит-тесты `bots/discord` (состояние и согласия, манифест, Ogg-фрагмент, индекс экспорта, права, команды, таймкоды) — без сети.
- Проверки репозитория: `npm ci`, `spec:validate`, `spec:validate:archive`, `npm test`.
- Живая приёмка — на ПК разработчика, тестовый сервер, только с согласия участников: 2–3 человека × 60 мин; затем 6–8 участников; прогон 3–4 ч; разрыв сети. Результаты — в #191.
