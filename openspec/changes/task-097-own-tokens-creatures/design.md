# Design

## Данные (песочница и сервер одинаково)

**Token** — новые необязательные поля, старые токены читаются как раньше:

| Поле | Значение |
|---|---|
| `kind: 'custom'` | Свой токен без листа и статблока: картинка + имя. Старые `hero`/`foe`/`item` не меняются. |
| `ownerId` | Кто поставил токен и управляет им (игрок). Нет поля — управляет мастер, как сейчас. |
| `role` | `'hero' \| 'companion' \| 'mount' \| 'summon' \| 'creature' \| 'prop'`. Нет поля — выводится из `kind` (hero → hero, foe → creature, item → prop). |
| `hp`, `hpMax`, `ac`, `speed`, `initBonus` | Статы «своего» токена. Уже есть у существ; у `custom` появляются по ПКМ → «Статы…». Пока `hpMax` нет — плашек нет. |

**Порядок слоёв** (`role` → слой): `prop` 0 → `mount` 1 → остальные 2. Внутри слоя — текущее правило «кого двигали последним — сверху». Конь всегда под всадником, даже если двигали коня.

**Герои игрока.** Источник истины — `Character.ownerId` (на сервере `characters.owner_id`, уже есть). `Member.characterId` остаётся «основным героем» для экрана выбора и совместимости. «Мои герои» = все герои кампании с `ownerId = я`.

**Creature (библиотека)** — личная, не привязана к кампании:
`{id, ownerId, name, img, size, type, alignment, ac, acNote, hp, hpFormula, speed{walk,fly,swim,climb,burrow}, stats{str…cha}, saves[], skills[], senses, languages, cr, traits[], actions[], bonusActions[], reactions[], legendary{count, actions[]}, source: 'manual'|'import', updatedAt}`. Каждая способность — `{name, text, attack?{bonus, reach|range}, damage?[{dice, type}], save?{ability, dc}, recharge?}` — те же поля, что у статблоков бестиария TASK-083, чтобы стол считал броски одинаково.

При постановке существа из библиотеки на сцену его статблок **копируется** в кампанию (`campaign.creatures[id]`, на сервере — таблица `campaign_creatures`), а токен ссылается на копию через `monsterId: 'lib:<id>'`. Так игроки и другие мастера не получают доступ к чужой библиотеке, а правка библиотеки не ломает идущую сцену.

**Импорт статблоков:** файл `.json` в формате `Creature` (одиночный или массив), проверка полей, отчёт «добавлено N, пропущено M (почему)». Другие форматы — см. открытые вопросы.

## Сервер (Supabase)

1. **`tokens.owner_id uuid`** (nullable, FK profiles). Индекс по `(campaign_id, owner_id)`.
2. **`is_my_character(c, ch)`** вместо единственного `my_character(c)`: герой кампании `c` с `owner_id = auth.uid()`. `my_character` остаётся для совместимости.
3. **`guard_token`** переписывается:
   - INSERT игроком: `kind='hero'` своего героя (любого из своих) **или** `kind in ('custom','foe')` с `owner_id = auth.uid()`, `role in ('companion','mount','summon','creature','prop')`, `hidden = false`.
   - UPDATE игроком своего токена (`owner_id = я` или свой герой): позиция, поворот, размер, свет, аура, высота, имя, картинка, статы и роль; `owner_id`, `campaign_id`, `hidden` — только мастер.
   - Чужие видимые незакреплённые — как сейчас (место и поворот при открытом перемещении).
   - DELETE: мастер — любой; игрок — свои `custom`/`foe` (призывы), но не героя.
4. **`creatures`** `(id text pk, owner_id uuid, data jsonb, updated_at)` — RLS: читать/писать только владелец. Лимит: 500 существ и 64 КБ на запись (триггер).
5. **`campaign_creatures`** `(campaign_id, id, data, added_by)` — RLS: мастер читает и пишет все; игрок читает только существ своих токенов (призывы), пишет — только добавляя свои.
6. **Бакет `tokens`** для картинок игроков: путь `<campaign>/<user>/<file>`, вставка — участник кампании в свою папку, чтение — участники кампании, до 5 МБ, PNG/JPEG/WebP.
7. **`supabase/tests/rls.sql`**: сценарии на всё выше (игрок ставит своего второго героя ✓, чужого героя ✗, свой призыв ✓, скрытый призыв ✗, удаляет свой призыв ✓, чужой ✗, правит статы своего custom ✓, чужого ✗, читает чужую библиотеку ✗, грузит картинку в чужую папку ✗).

## Интерфейс

- **Нижний бар игрока:** кнопка «Добавить» → «Свой токен (картинка)», «Существо (призыв)», «Мой герой» (если героев несколько и кого-то нет на сцене).
- **ПКМ по своему токену:** «Статы…» (хиты, КД, скорость, инициатива), «Роль…» (герой-напарник, ездовое, призыв, существо, предмет), «Картинка…», «Удалить».
- **Выбор героя:** у игрока, у которого уже есть герой, — «Добавить ещё героя» (новый лист или свободный герой кампании).
- **Главная → «Существа»:** список библиотеки, «Создать», «Импорт файла»; конструктор — характеристики, спасброски, навыки, чувства, особенности, действия (с бросками атаки и урона), бонусные действия, реакции, легендарные.
- **Стол → панель «Существа»:** вкладки «Бестиарий» и «Мои»; у игрока — только для призыва.

## Порядок работ

1. Данные и сервер: миграции, `guard_token`, RLS, бакет, тесты RLS, `docs/data.md`. **L2 — review Яры.**
2. Песочница: те же правила в `campaign.js` (`canControlToken`, «мои герои»), слой по роли, статы custom.
3. Интерфейс стола: добавление своего токена, «Статы…», «Роль…», призывы, несколько героев.
4. Библиотека: главная → «Существа», конструктор, импорт, панель «Мои» за столом.

Шаги 2–4 зависят от 1, но могут идти отдельными PR после подтверждения плана; каждый — со своей Issue.

## Открытые вопросы (нужен ответ до кода)

1. **Места в кампании:** лимит `seats` считает игроков или героев? Предложение — игроков; героев у игрока до 3.
2. **Инициатива призыва:** ходит на инициативе владельца (по умолчанию) или бросает свою? Предложение — на инициативе владельца, мастер может отделить.
3. **Импорт:** только наш JSON или ещё 5e.tools / Foundry? Предложение — сначала наш формат, остальные — отдельной задачей после проверки лицензий источников.
4. **Видимость статов:** видят ли другие игроки хиты чужих призывов и custom-токенов? Предложение — как у союзных героев (точные хиты видны).
5. **Библиотека мастера для игроков:** может ли мастер разрешить игрокам призывать существ из своей библиотеки? Предложение — да, флаг «доступно игрокам» у существа.

## Риски

- `guard_token` — общий контракт сервера: перепись без полного прогона `rls.sql` может открыть игроку чужие токены. Митигирует: тесты на каждое правило, review Яры.
- Слой по роли меняет порядок наложения у всех: старые сцены без `role` выглядят как раньше (роль выводится из `kind`).
- Объём: четыре порции; без шага 1 остальное в серверном режиме не заработает.
