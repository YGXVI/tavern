# Design

## Данные (песочница и сервер одинаково)

**Token** — новые необязательные поля, старые токены читаются как раньше:

| Поле | Значение |
|---|---|
| `kind: 'custom'` | Свой токен без листа и статблока: картинка + имя. Старые `hero`/`foe`/`item` не меняются. |
| `ownerId` | Кто поставил токен и управляет им (игрок). Нет поля — управляет мастер, как сейчас. |
| `role` | `'hero' \| 'companion' \| 'mount' \| 'summon' \| 'creature' \| 'prop'`. Нет поля — выводится из `kind` (hero → hero, foe → creature, item → prop). |
| `hp`, `hpMax`, `ac`, `speed`, `initBonus` | Статы «своего» токена. Уже есть у существ; у `custom` появляются по ПКМ → «Статы…». Пока `hpMax` нет — плашек нет. |

**Порядок слоёв** (`role` → слой): `prop` 0 → `mount` 1 → остальные 2. Внутри слоя — текущее правило «кого двигали последним — сверху». Конь всегда под всадником, даже если двигали коня.

**Герои игрока.** Источник истины — `Character.ownerId` (на сервере `characters.owner_id`, уже есть). `Member.characterId` остаётся «основным героем» для экрана выбора и совместимости. «Мои герои» = все герои кампании с `ownerId = я`.

**Creature (библиотека)** — личная, не привязана к кампании:
`{id, ownerId, name, img, statblockImage?, size, type, alignment, ac, acNote, hp, hpFormula, speed{walk,fly,swim,climb,burrow}, stats{str…cha}, saves[], skills[], senses, languages, cr, traits[], actions[], bonusActions[], reactions[], legendary{count, actions[]}, source: 'manual'|'import', updatedAt}`. Каждая способность — `{name, text, attack?{bonus, reach|range}, damage?[{dice, type}], save?{ability, dc}, recharge?}` — те же поля, что у статблоков бестиария TASK-083, чтобы стол считал броски одинаково.

При постановке существа из библиотеки на сцену его статблок **копируется** в кампанию (`campaign.creatures[id]`, на сервере — таблица `campaign_creatures`), а токен ссылается на копию через `monsterId: 'lib:<id>'`. Так игроки и другие мастера не получают доступ к чужой библиотеке, а правка библиотеки не ломает идущую сцену.

**Статблок картинкой:** `statblockImage` — ссылка на картинку в хранилище; при копировании в кампанию картинка копируется в папку кампании. Видят её мастер кампании и владелец существа.

## Сервер (Supabase)

1. **`tokens.owner_id uuid`** (nullable, FK profiles). Индекс по `(campaign_id, owner_id)`.
2. **`is_my_character(c, ch)`** вместо единственного `my_character(c)`: герой кампании `c` с `owner_id = auth.uid()`. `my_character` остаётся для совместимости.
3. **`guard_token`** переписывается:
   - INSERT игроком: `kind='hero'` своего героя (любого из своих) **или** `kind in ('custom','foe')` с `owner_id = auth.uid()`, `role in ('companion','mount','summon','creature','prop')`, `hidden = false`.
   - UPDATE игроком своего токена (`owner_id = я` или свой герой): позиция, поворот, размер, свет, аура, высота, имя, картинка, статы и роль; `owner_id`, `campaign_id`, `hidden` — только мастер.
   - Чужие видимые незакреплённые — как сейчас (место и поворот при открытом перемещении).
   - DELETE: мастер — любой; игрок — свои `custom`/`foe` (призывы), но не героя.
4. **`creatures`** `(id text pk, owner_id uuid, data jsonb, updated_at)` — RLS: читать/писать только владелец. Лимит: 500 существ и 64 КБ на запись (триггер).
5. **`campaign_creatures`** `(campaign_id, id, data, added_by)` — RLS: мастер читает и пишет все; игрок читает существ своих призывов, пишет — только добавляя свои. Хиты призыва лежат на токене и видны всем участникам.
6. **Бакеты.** `tokens` — картинки токенов игроков: `<campaign>/<user>/<file>`, вставка — участник в свою папку, чтение — участники кампании. `library` — картинки статблоков: `<user>/<file>`, только владелец; копия в кампании — `tokens/<campaign>/creatures/<file>`, читают мастер и владелец. Везде до 5 МБ, PNG/JPEG/WebP.
7. **Без мест.** `join_campaign` больше не возвращает `full`, триггер членства не считает места, `invite_preview` отдаёт число игроков без лимита.
8. **`supabase/tests/rls.sql`**: сценарии на всё выше (игрок ставит своего второго героя ✓, чужого героя ✗, свой призыв ✓, скрытый призыв ✗, удаляет свой призыв ✓, чужой ✗, правит статы своего custom ✓, чужого ✗, читает чужую библиотеку ✗, грузит картинку в чужую папку ✗, вступает в кампанию, где уже 12 игроков ✓).

## Интерфейс

- **Нижний бар игрока:** кнопка «Добавить» → «Свой токен (картинка)», «Существо (призыв)», «Мой герой» (если героев несколько и кого-то нет на сцене).
- **ПКМ по своему токену:** «Статы…» (хиты, КД, скорость, инициатива), «Роль…» (герой-напарник, ездовое, призыв, существо, предмет), «Картинка…», «Удалить».
- **Выбор героя:** у игрока, у которого уже есть герой, — «Добавить ещё героя» (новый лист или свободный герой кампании), без ограничения числа.
- **Кампания:** из окон создания, настроек и приглашения уходят «Мест за столом» и «N из M мест»; в приглашении — «N игроков».
- **Главная → «Существа»:** список библиотеки, «Создать», «Статблок картинкой»; конструктор — характеристики, спасброски, навыки, чувства, особенности, действия (с бросками атаки и урона), бонусные действия, реакции, легендарные.
- **Стол → панель «Существа»:** вкладки «Бестиарий» и «Мои»; у игрока — только для призыва, из бестиария и своей библиотеки. У существа со статблоком-картинкой во вкладке статблока — картинка.

## Порядок работ

1. Данные и сервер: миграции, `guard_token`, RLS, бакеты, снятие мест, тесты RLS, `docs/data.md`. **L2 — review Яры.**
2. Песочница: те же правила в `campaign.js` (`canControlToken`, «мои герои»), слой по роли, статы custom.
3. Интерфейс стола: добавление своего токена, «Статы…», «Роль…», призывы, несколько героев.
4. Библиотека: главная → «Существа», конструктор, статблок картинкой, панель «Мои» за столом.

Шаги 2–4 зависят от 1, но могут идти отдельными PR после подтверждения плана; каждый — со своей Issue.

## Решения sol0139 (30.10 13:03 +05:00)

1. **Мест нет.** Лимит `seats` убирается целиком: игроков и героев у игрока сколько угодно. Поле `seats` в старых данных остаётся, но не читается.
2. **Инициатива призыва.** Призыв сам в бой не попадает (ходит вместе с владельцем). Если он ходит по своей инициативе, мастер добавляет его в бой вручную, как любое существо.
3. **Импорт статблоков — картинкой.** Мастер загружает картинку статблока (PNG/JPEG/WebP до 5 МБ) в существо библиотеки; за столом во вкладке статблока видна картинка. Числа для плашек и боя (хиты, КД, скорость, инициатива) он вписывает в конструкторе. Распознавание текста с картинки — отдельная задача: нужен распознаватель в браузере или платный сервис, это отдельное решение.
4. **Хиты призывов видны всем** игрокам, как у союзных героев.
5. **Библиотека мастера игрокам не выдаётся.** Игрок призывает из бестиария или своей библиотеки.

## Риски

- `guard_token` — общий контракт сервера: перепись без полного прогона `rls.sql` может открыть игроку чужие токены. Митигирует: тесты на каждое правило, review Яры.
- Слой по роли меняет порядок наложения у всех: старые сцены без `role` выглядят как раньше (роль выводится из `kind`).
- Объём: четыре порции; без шага 1 остальное в серверном режиме не заработает.
