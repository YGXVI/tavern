**Пометки статуса** во всём документе:

- **Э1** — первый этап TASK-097, его и просим подтвердить;

## 1. Сущности и источник истины

| Сущность | Что это | Где хранится | Источник истины для | Статус |
|---|---|---|---|---|
| **Шаблон** | Статблок для многократного использования | Бестиарий SRD в коде, только чтение (есть). Личная библиотека пользователя `creatures` (Э1) | Характеристики, действия, особенности | есть / Э1 |
| **Копия шаблона в кампании** | Снимок шаблона на момент первой постановки | `campaign_creatures` | Статблок всех токенов этого вида в кампании | Э1 |
| **Экземпляр героя** | Лист персонажа | `characters`; поля листа расширяет TASK-004 (#61) | Хиты, временные хиты, состояния, ресурсы, спасброски от смерти, тёмное зрение, свет | есть |
| **Экземпляр существа** | Сам токен существа | `tokens.data` | Хиты, временные хиты, состояния, КД, скорость, бонус инициативы | есть |
| **Экземпляр своего токена** | Сам токен: картинка игрока и, если заданы, статы | `tokens.data` | То же, что у существа | Э1 |
| **Токен** | Фишка на сцене | `tokens` | Место, размер, поворот, высота, свет и аура, видимость, закрепление, порядок наложения | есть |
| **Связь** | Отношение между токенами | Поле ведомого токена: `summonedBy` (Э1); «едет на» — цель | Чей это призыв; кто на ком едет | Э1 / цель |

### Ответы на вопросы о сущностях

- **Два токена одного героя.** Их не бывает: у героя не больше одного токена на всю кампанию (инвариант И1, есть). «Герой на сцену» переносит его фишку с другой сцены. Хиты и состояния — в листе, поэтому на любой сцене они одни.
- **Два одинаковых существа.** Это два независимых экземпляра: свои хиты и состояния. Общая у них только копия шаблона (статблок).
- **Удаление токена.**
  - Героя: лист остаётся, фишка исчезает (есть, с подтверждением).
  - Существа или своего токена: экземпляр исчезает вместе с токеном. Копия шаблона в кампании остаётся.
  - Запись в бою удаляется (есть) и **должна возвращаться при отмене**. Сейчас отмена возвращает только токен — исправить в Э1.
- **Перенос между сценами.** Токен переносится целиком вместе со своим экземпляром (есть, через переходы). Призывы владельца сами не переносятся — см. вопрос В6.
- **Копирование.** «Дублировать» есть только у не-героев (есть). Сейчас копия получает те же текущие хиты и состояния. Предложение для Э1: полные хиты и без состояний (вопрос В7).
- **Обновление шаблона в библиотеке** не меняет ни копию в кампании, ни экземпляры (Э1). Явная кнопка «Обновить из библиотеки» — цель.

## 2. Признаки токена — независимые оси

Ни одна логика не завязана на одно поле «роль». Каждая ось меняется отдельно.

| Ось | Значения | Откуда берётся | Кто меняет | Статус |
|---|---|---|---|---|
| Вид `kind` | `hero` · `foe` (существо) · `custom` (свой) · `item` | Задаётся при создании, потом не меняется (И2) | — | есть, `custom` — Э1 |
| Союзность `disposition` | враг · нейтрал · союзник · тайный | Поле токена; без поля у `foe` — враг | Мастер; владелец своего токена — Э1 | есть |
| Владелец | Пользователь или нет (тогда мастер) | Герой — `characters.owner_id` (есть); свой токен и призыв — `tokens.owner_id` (Э1) | Мастер | есть / Э1 |
| Временные управляющие | Список пользователей | Поле токена | Мастер | цель |
| Призыв `summonedBy` | id токена призывателя | Поле токена-призыва | Ставится при призыве | Э1 |
| Ездовое `mount` | да / нет | Поле токена | Владелец или мастер | Э1 (только слой) |
| Едет на `riding` | id токена ездового | Поле токена всадника | — | цель |
| Слой | предмет 0 · ездовое 1 · обычный 2 | Выводится: `item` → 0; `mount` → 1; остальные → 2. Ручное переопределение `layer` хранится отдельно (И6) | Владелец или мастер | Э1 |
| В бою | Есть запись в `combat.entries` | Бой | Мастер | есть |

**Сочетания.** Конь может быть одновременно призывом и ездовым: `summonedBy` + `mount`. Свой токен может иметь любую союзность и, после «Статов…», участвовать в бою. Предмет в бою не участвует (И3).

### Инварианты

- **И1.** У героя не больше одного токена в кампании.
- **И2.** Вид токена после создания не меняется. Чтобы «превратить» свой токен в существо, его пересоздают.
- **И3.** Предмет не участвует в бою и не показывает плашек.
- **И4.** Владелец своего токена или призыва — активный участник кампании. При выходе игрока см. вопрос В2.
- **И5.** Призыв ссылается на токен с тем же владельцем. Если призыватель удалён, ссылка снимается, а призыв остаётся (Э1, вопрос В6).
- **И6.** Слой выводится из признаков; ручное переопределение не меняет ни вид, ни ездовое.
- **И7.** Скрытые токены игрокам с сервера не приходят (есть).

## 3. Матрица прав

Кто действует:

- **М** — мастер;
- **В** — владелец: у героя — владелец листа, у своего токена и призыва — `owner_id`;
- **У** — временно управляющий (цель);
- **И** — другой игрок;
- **З** — ожидающий заявку или посторонний.

**ОП** — «открытое перемещение», настройка кампании, по умолчанию включена.

| Действие | М | В | У (цель) | И | З |
|---|---|---|---|---|---|
| Видеть токен | Все, и скрытые | Видимые; свой скрытый — **В1** | Как В | Видимые | ✗ |
| Видеть хиты и КД | ✓ | ✓ | ✓ | Герои и призывы — ✓ (решение sol0139); существа — по настройке «точные хиты врагов» (есть) | ✗ |
| Выделять, двигать, поворачивать | ✓ (Alt — сквозь стены) | ✓ | ✓ | При ОП — видимые незакреплённые (есть) | ✗ |
| Размер, свет, аура, высота | ✓ | Свой герой — есть; свой токен и призыв — Э1 | ✗ | ✗ | ✗ |
| Имя, картинка, союзность, ездовое, слой | ✓ | Свой токен и призыв — Э1 | ✗ | ✗ | ✗ |
| Хиты, временные, состояния | ✓ | Герой (в листе) — есть; свой токен и призыв — Э1 | цель | ✗ | ✗ |
| Править лист героя | ✓ | ✓ | ✗ | ✗ (смотреть — по TASK-004) | ✗ |
| Бросать атаки и спасброски | ✓ | ✓ | цель | За героев — ✓ («играть за товарища», решение 30.10 09:19); за чужие призывы и существ — ✗ | ✗ |
| Добавить в бой, убрать из боя | ✓ | ✗ (решение sol0139: призывы добавляет мастер) | ✗ | ✗ | ✗ |
| Бросить инициативу | ✓ | Один раз за бой: герой — есть; призыв — Э1 | цель | За героев — ✓ (есть) | ✗ |
| Закончить ход | ✓ | В свой ход | цель | За героя — ✓ (есть) | ✗ |
| Скрыть, показать, закрепить | ✓ | ✗ | ✗ | ✗ | ✗ |
| Поставить на сцену | Любой | Своего героя — есть; свой токен и призыв — Э1 | ✗ | ✗ | ✗ |
| Удалить | ✓ | Свой токен и призыв — Э1; героя — ✗ (убирает мастер) | ✗ | ✗ | ✗ |
| Сменить владельца | ✓ | ✗ | ✗ | ✗ | ✗ |

**Три вида владения не смешиваются.**

- Библиотеку существ видит и правит только её хозяин. Мастер игрокам свою библиотеку не выдаёт (решение sol0139).
- Экземпляром (статами) распоряжается его владелец.
- Управление токеном — это движение: владелец, временный управляющий (цель) или любой при ОП.

**Отзыв доступа и выход игрока.**

- Герои остаются листами без владельца (есть).
- Свои токены и призывы — вопрос **В2**. Предложение: остаются на сцене, управление переходит мастеру.
- Ожидающий заявку не видит ничего, кроме заявки (есть).

## 7. Связи между токенами

| | Призыватель → призыв (Э1) | Всадник → ездовое (цель; в Э1 — только слой) |
|---|---|---|
| Направление | Призыв ссылается на призывателя (`summonedBy`), владелец — игрок призывателя | Всадник ссылается на ездовое (`riding`) |
| Длительность | Пока призыв на сцене; таймеры заклинаний — цель | Пока не спешился |
| Движение | Отдельно | Вместе; тратится скорость ездового (цель) |
| Посадка и спешивание | — | Команды в ПКМ (цель) |
| Смена сцены | Призыв не переносится сам (В6) | Вместе (цель) |
| Удаление или смерть ведущего | Призыв остаётся, ссылка снимается | Всадник спешивается (цель) |
| Потеря управления | По правилу В2 | Цель |
| Бой | Отдельная запись, добавляет мастер | Цель |

**«Конь под всадником» в Э1 — это только порядок отрисовки, не езда.** Флаг «ездовое» кладёт токен в нижний слой; никакой механики посадки, общего движения или скорости в Э1 нет.

Правила инициативы и движения разных призывов разные. Э1 их не обобщает: всё необычное решает мастер вручную.

**Напарник** (второй герой игрока) — это обычный лист героя с тем же владельцем. Его поля и источник истины — TASK-004 (#61, Codex); в TASK-097 нет второй сущности героя.

## 8. Синхронизация и целостность

| Данные | Источник истины |
|---|---|
| Лист героя | `characters` |
| Существо, свой токен, призыв | `tokens.data` |
| Бой | `combats` |
| Копия шаблона в кампании | `campaign_creatures` (Э1) |
| Библиотека | `creatures` (Э1) |
| Картинки | Хранилище (бакеты `tokens`, `library`) |

**Как сейчас (есть).**

- Изменение применяется оптимистично и уходит на сервер очередью; обрыв сети — до 8 повторов; отказ сервера — сообщение и перезагрузка кампании.
- Правка токена отправляет **всю строку**: побеждает последняя запись, без проверки версии (аудит TASK-035, #57/#59, находка B1).
- Несколько операций идут не одной транзакцией (B5).
- Отмена восстанавливает массивы целиком (N5).

**Что делаем в Э1.**

1. **Связанные изменения — одной транзакцией.** Постановка призыва и копии шаблона идёт функцией сервера `place_creature(...)`, а не двумя отдельными записями.
2. **Удаление во время чужой правки.** Правка получает отказ, кампания перезагружается (есть) — плюс понятное сообщение «Токен удалён мастером».
3. **Одновременные правки одного токена** — вопрос **В5**:
   - (а) оставить «последний побеждает» и записать это как известное ограничение;
   - (б) частичная правка токена функцией сервера `patch_token(id, changes)`: двигающий не затирает хиты.
   Предложение — (б) только для токенов, остальное по аудиту #57.

Вторую сущность героя в обход листа #61 не создаём. Изменения сервера согласуем с контрактом #8 и аудитом #57.

## Данные Э1

**Token** — новые необязательные поля. Без них токен ведёт себя как раньше.

| Поле | Значение |
|---|---|
| `kind: 'custom'` | Свой токен |
| `ownerId` | Владелец (на сервере — колонка `owner_id`) |
| `summonedBy` | id токена призывателя |
| `mount` | Ездовое — только слой |
| `layer` | Ручное переопределение слоя 0–2 |
| `hp`, `hpMax`, `ac`, `speed`, `initBonus` | Статы своего токена; плашки появляются, когда задан `hpMax` |

**Creature** (личная библиотека):

```
{id, ownerId, name, img, statblockImage?, size, type, alignment,
 ac, acNote, hp, hpFormula, speed{walk, fly, swim, climb, burrow},
 stats{str…cha}, saves[], skills[], senses, languages, cr,
 traits[], actions[], bonusActions[], reactions[], legendary{count, actions[]},
 source: 'manual'|'image', updatedAt}
```

Каждая способность — `{name, text, attack?{bonus, reach|range}, damage?[{dice, type}], save?{ability, dc, who: 'target'|'self'}, recharge?}`. Поле `who` учитывает замечание из ревью #107: спасбросок цели и спасбросок самого существа нельзя смешивать.

**Копия шаблона** в кампании: `campaign.creatures[id]`, токен ссылается на неё через `monsterId: 'lib:<id>'`.

## Сервер Э1

1. `tokens.owner_id uuid` (может быть пустым) и индекс `(campaign_id, owner_id)`.
2. Функция `is_my_character(c, ch)` — проверка по `characters.owner_id`. `my_character` остаётся для совместимости.
3. `guard_token` переписывается по матрице раздела 3:
   - вставка игроком — свой герой, свой токен или призыв с `owner_id = auth.uid()`, не скрытый;
   - правка — свои поля по матрице;
   - удаление — свой токен и призыв.
4. Функции `place_creature(...)` (одна транзакция) и `patch_token(...)` — если по В5 выбран вариант (б).
5. Таблицы:
   - `creatures` — читает и пишет только владелец; не больше 500 записей и 64 КБ на запись;
   - `campaign_creatures` — мастер всё; игрок читает существ своих призывов и добавляет свои.
6. Бакеты, везде до 5 МБ, PNG/JPEG/WebP:
   - `tokens` — `<campaign>/<user>/…`;
   - `library` — `<user>/…`;
   - копия картинки статблока — в папке кампании, читают мастер и владелец.
7. Места не меняются: их проверки уже считают игроков.
8. `supabase/tests/rls.sql`: по сценарию на каждую клетку матрицы и на каждый отказ из раздела 4.
