# Design

## Почему подписка без фильтра, а не рассылка «удалено» по каналу

- Рассылка (как `hidden-ids`) покрыла бы только удаления, сделанные клиентом. Каскады в базе (удаление сцены → её токены и рисунки), удаление участника мастером, будущие серверные функции её бы не прислали.
- Подписка на DELETE без фильтра получает все удаления строк, кто бы их ни сделал.

## Безопасность и объём

- RLS к событиям DELETE не применяется (документация Supabase), а в событии — только первичный ключ. Чужие данные не утекают, видны лишь случайные id удалённых строк чужих кампаний.
- Обработчик сверяет ключ с кэшем кампании; чужое — пропускается, без пересборки и перерисовки.

## Проверка

- Юнит-тест `ownsDeleted`: своё удаление — да; чужой id — нет; ключи `scene_id` для `scene_secrets`/`scene_explored`.
- Живая проверка двумя аккаунтами после деплоя (Realtime в стенде не моделируется): рисунок, токен, герой — удалил один, пропало у другого без перезагрузки.

## Откат

Revert одного коммита; данных и схемы не касается.
