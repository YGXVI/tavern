# Расчёт урона · D&D 5e 2014 · TASK-009
Независимый ES-модуль без зависимостей и без побочных эффектов. Архитектура проекта buildless; существующий `dist/engine.js` бросает простые кубы и сортирует инициативу, но не содержит правил заклинаний. `dist/**` и `tests/**` зарезервированы TASK-007. Каталог 524 записей находится в PR #4, пока не в main. Этот пакет не меняет каталог, характеристики, броски, HP, сохранения и UI. Данные можно подключить после интеграции PR #4; модуль пока не опубликован в интерфейсе.
## Результат и границы
Обработаны все **524 ID**. **53** заклинания поддерживаются в пределах расчёта формул урона; **471** запись требует проверки. Последнее число включает непроверенные заклинания без прямого урона: это НЕ 471 неподдерживаемое атакующее заклинание. Отсутствие `damage` в API не доказывает отсутствие урона. `Sleep` специально исключён: его кубики — пул хитов, не урон.
Полный список ID/причин: `report.json`; человекочитаемый список: `REPORT.md`. Неизвестный профиль возвращает `manual_review`, никогда `0` или придуманную формулу. Неподтверждённые механики перечислены в отчёте, в частности выбор типа усиления Flame Strike, тип урона Spirit Guardians, растения Blight, накопление Delayed Blast Fireball, режимы Arcane Hand, призывы, превращения, случайные ветви, пределы хитов и отражение.
## Контракт
`damage.json` — дополнение по существующим `dndsu:spell:<id>`, не второй каталог. Названия, описание, школу, компоненты и прочие характеристики не копируем в записи урона. Базовый круг и концентрация проверены при сопоставлении; их сохранённый снимок нужен чистому расчёту. `rules.json` — единственный редактируемый источник проверенных профилей. `damage.json`, `levels.json`, `report.json`, `REPORT.md` производные, вручную не редактировать. Хеш исходного каталога в отчёте позволяет обнаружить несовместимую версию.
`calculate(entry, {slotLevel})`: целый круг от базового до 9. Для заговоров только `{characterLevel}` (1–20): пороги 1/5/11/17. Расчёт использует уровень персонажа, не класса. `allLevels(entry)` перечисляет допустимые варианты. Нет экстраполяции по произвольной API-таблице: только явно проверенное правило `slot`, `character`, `none`, включая шаг в два круга.
Результат содержит компоненты с **типом, формулой, областью (`per_unit` / `per_target_event`), событием и условием**. Это формула при выполненном условии нанесения урона, до разрешения попадания/спасброска. Для особых половинных повреждений (например промах Acid Arrow) берётся половина результата исходного броска по описанию, не половина количества кубиков. Система не меняет существующее разрешение спасбросков, сопротивлений, критов, округления, особенностей класса и HP; это не симулятор боя и не обещание реализации всех эффектов 53 заклинаний.
`units` и `unitKind` обозначают снаряды/отдельные атаки одного применения. Magic Missile: 1d4+1 за снаряд, 3+(круг−1) снарядов. Scorching Ray: 2d6 за попавший луч, 3+(круг−2) отдельных атак. Eldritch Blast: 1d10 за луч, растёт число лучей. Chain Lightning: 10d8 одной цели на любом круге, растёт `targetLimit`, а не урон цели.
`aggregate(result, {componentKey: count})` считает сумму только явно выбранных событий/попаданий. Укажите каждый компонент, в том числе 0 для не сработавшей фазы; неизвестные, отрицательные, дробные и превышающие число лучей количества отклоняются. Число целей, попадания, повторные действия и срабатывания устанавливает вызывающий код согласно описанию. Это не автоматическая сумма урона всей концентрации. На одной цели при всех попаданиях Scorching Ray 3-го круга: `aggregate(result, {damage: 4})` → `8d6`. Для разных целей вызывайте по распределённым попаданиям отдельно; не выдавайте общую сумму за урон одной цели.
Acid Arrow имеет отдельные initial/later, Wall of Ice разные прибавки 2d6/1d6, Ice Storm усиливает только дробящий компонент, Meteor Swarm не умножается на четыре метеора при перекрытии. Типы урона не складываются в одну безымянную формулу. Повторные эффекты имеют явные условия событий. Концентрация — флаг, не число раундов.
Spiritual Weapon: параметр `spellModifier` или символическое `+MOD`; сумма без явного модификатора отклоняется. Call Lightning: `storm: true` добавляет 1d10 только если при накладывании уже есть буря на открытом воздухе. Остальные параметры окружения автоматически не определяются.
## Источники и сопоставление
Дополнительный источник — https://www.dnd5eapi.co/api/2014/spells (319 записей), сохранён в `srd-2014.json`. Это общественный структурированный SRD API, не официальный сервис Wizards. Основа механики — SRD 5.1 (2014): https://media.dndbeyond.com/compendium-images/srd/5.1/SRD_CC_v5.1.pdf . Редакция 2024 не используется.
Сопоставление: уникальное нормализованное проверенное английское название + совпадение круга и концентрации. Переименованные SRD-заклинания — только явная таблица `aliases` с точным существующим ID и ожидаемым именем; fuzzy matching нет. Расхождение отправляется на проверку, исходник не перезаписывается. Stable API index, URL и хеш доказательства сохраняются. Нет автоматического вывода «нет усиления» только из отсутствующей API-таблицы. Проверенные постоянные профили заданы явно. API неполон: Acid Arrow/Wall of Ice содержат не все фазы; Phantasmal Killer/Wall of Fire неполные таблицы, Magic Missile хранит общий урон, Eldritch Blast требует отдельного учёта лучей.
## Запуск
```sh
# Путь к существующему каталогу PR #4; никаких запросов сети:
node modules/spell-damage/build.mjs /absolute/path/to/data/spells/spells.json
node --test modules/spell-damage/engine.test.js
npm test
```
62 теста модуля и 6 существующих тестов. Новые тесты запускаются отдельно: package.json/CI принадлежат общей архитектуре и здесь не меняются. CI пока выполняет только существующий npm test. Тесты сверяют все круги, граничные значения, независимые SRD-таблицы и специальные случаи. Проверка UI отсутствует: интерфейс не менялся. Для обновления сетевого снимка отдельно `python3 modules/spell-damage/fetch_srd.py`; затем сверить различия, правила и пересобрать. Сеть не используется при тестах/расчётах. Snapshot фиксирован, новые данные не признаются автоматически проверенными.
